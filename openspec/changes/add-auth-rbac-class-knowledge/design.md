## Context

这是从零补做第二课的设计初稿，为第三课实现提供依据。本机有 Node.js 24 内置 SQLite，故选 Node.js + SQLite；若改回 Python 栈须同步修改代码和任务。补充第三课的会话撤销与安全验收要求。

## Goals / Non-Goals

目标：登录可用、学生只读、班级边界不可绕过、上传双表入库、第三方可用 Compose 复现。非目标见 proposal.md。

## Decisions

### Decision 1: 使用 Node.js、SQLite 与单实例服务

小型课程项目先用一个应用和一个数据库文件，减少需要排查的组件。Node.js 24 内置 SQLite，省去额外数据库依赖。备选是 Flask + SQLite；本机没有 Python 开发工具，故先不采用，功能验收保持一致。容器单进程，数据库与上传文件各有 Docker 命名数据卷；本轮不声称支持高可用或多实例。

### Decision 2: 服务端会话与班级来源

Cookie 只保存随机会话令牌，数据库保存令牌哈希、用户 ID 与过期时间。每次业务请求从会话关联用户表取得 role 和 class_id，不相信浏览器提交的班级或角色。登出删除会话记录，复制的旧 Cookie 随即失效。有效期默认 8 小时。

Cookie 设置 HttpOnly、SameSite=Lax；本地 HTTP 不设置 Secure，未来 HTTPS 环境必须启用。状态变更请求使用 CSRF 令牌。备选是完全自包含的 JWT 或 Flask 默认签名 Cookie；本轮不采用，因为服务端会话撤销更直观，也避免把“签名 Cookie”误认为服务端会话存储。

### Decision 3: 跨班统一返回 404

列表、搜索、详情、下载查询均以当前用户 class_id 为条件。跨班资源和不存在资源都返回相同的 404，避免透露资源是否存在。备选是 403；它可以表达无权访问，但可能透露该资源存在。学生调用上传接口则明确返回 403。未登录 API 返回 401，页面重定向登录。

### Decision 4: 上传失败不留下不完整资料

先检查登录、角色、CSRF、扩展名、大小与 UTF-8 编码，再写文件。只接受非空 .txt/.md，最大 2 MiB，空正文或非法编码返回 400，超限返回 413。磁盘名用服务端随机 ID，客户端文件名不能决定存储路径。

materials 与 knowledge_entries 两张表在同一事务中写入；每条知识库记录保存 material_id、class_id、body_text。成功返回 201。可捕获的文件或数据库错误必须回滚双表并删除已写文件；数据库不可用返回 503。备选是两次独立提交，会产生材料有了但知识库缺失的问题。磁盘和数据库不是同一个事务：进程突然中止可能留下孤立文件；启动时把仅符合服务端随机命名规则、且没有材料记录的文件移入 `.orphaned/` 隔离目录，保留恢复可能，不将其作为活动材料。

### Decision 5: /health 只表示应用进程可响应

GET /health 无需登录，正常返回 200 和 JSON，不访问数据库。数据库故障让依赖它的业务接口返回 503，不能错误地把用户判为未登录。备选是在 /health 查数据库；本轮区分进程存活与业务依赖可用性，避免混用。

### Decision 6: 口令、配置与页面

口令用 Node.js 内置 scrypt 加随机盐哈希保存。备选 bcrypt/argon2 需要额外安装包；本轮为可离线复现选 scrypt。真实密钥及预置账号口令从未入库的 .env 读取；.env.example 仅提供变量说明。禁止日志记录口令、会话令牌和密钥。初始账号覆盖 A/B 两班，各有教师与学生，重复初始化不覆盖已有数据。

Markdown 渲染禁用原始 HTML，并清理危险链接；下载经过鉴权，上传目录不作为公开静态目录。页面提供登录、资料列表、标题搜索、详情、下载及教师上传，并支持主题和列表/网格切换。

## Migration Plan

从空库建表、建立测试班级与用户，分步实现后验收。Apply 只修改 change 中的规约；全部验证通过后再 Archive 合并到 openspec/specs。实现顺序见 tasks.md。

## Risks / Trade-offs

- SQLite 与单实例适合当前范围，不是生产高可用承诺。
- 需要真实 Docker 运行才能确认 Compose 交付；仅有配置文件不算通过。
- 初稿由助手协助起草，需本人理解并核对设计取舍，不能把尚未发生的评审、互验或测试写成已完成。
